# Editorial Checklist

## Reader value
- [ ] Clear reader promise, delivered by the end
- [ ] Strong opening (no throat-clearing)
- [ ] Every section earns its place (no orphans, no padding)
- [ ] Useful examples the reader can reuse
- [ ] Strong conclusion (consolidates, doesn't introduce)
- [ ] No unnecessary repetition

## Structure
- [ ] Section titles state claims/questions, not topics
- [ ] Ordered by reader need, not author discovery order
- [ ] Explicit transitions between sections
- [ ] Depth where it matters (the hard part gets the words)

## Clarity
- [ ] Sentences under ~35 words (mostly)
- [ ] Paragraphs 3-6 sentences, one idea each
- [ ] Every acronym/term defined on first use
- [ ] Concrete numbers instead of vague qualifiers where possible

## Voice & contribution
- [ ] The author is present (experience, judgment, or position)
- [ ] No generic AI-cadence filler ("In today's fast-paced world...")
- [ ] Sounds like the author (check `.article-craft/voice.md` if present)
- [ ] Title + subtitle accurately represent the article

## Technical (for technical articles)
- [ ] Code tested as published; versions stated
- [ ] Assumptions labeled as assumptions
- [ ] Trade-offs explained on both sides
- [ ] Failure modes / edge cases covered
- [ ] Sources included for non-obvious claims

## Final pass
- [ ] Read from beginning to end, out loud if possible
- [ ] Fact-check workflow run on load-bearing claims
- [ ] Originality review done (if sources were used)
- [ ] Platform check done (Medium or generic)
- [ ] Proofread: typos, broken links, image alt text
